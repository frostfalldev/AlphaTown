# AlphaTown — project settings

Applied by **AlphaTown ▸ Setup ▸ Apply All Project Settings**, which runs three passes in
dependency order:

1. `PlayerSettingsConfigurator` — identity, orientation, platform targets
2. `QualityLevelConfigurator` — the three quality levels and their URP assets
3. `MobileUrpConfigurator` — tunes each URP asset ([URP_MOBILE_PROFILE.md](URP_MOBILE_PROFILE.md))

Values live in `Assets/AlphaTown/Code/Editor/Setup/AlphaTownProjectProfile.cs`. Change them
there and re-run, so a settings change reviews as a one-line diff instead of an opaque
`ProjectSettings.asset` blob.

> **Why a script and not the .asset files?** `ProjectSettings/` is generated by Unity Hub on
> your machine and is not in this repo, so there is nothing here to hand-edit. Scripting it also
> makes the configuration re-runnable, CI-able and reviewable — which hand-edited YAML is not.

## 6. Quality levels

The template's levels are **replaced** by exactly three, each with its own URP asset. The names
matter: `MobileUrpConfigurator` maps "low" to its Performance tier and "high" to Fidelity, so the
rendering profile follows automatically.

| | Low | Medium | High |
| --- | --- | --- | --- |
| URP asset | `AlphaTown_Low` | `AlphaTown_Medium` | `AlphaTown_High` |
| Anisotropic textures | Disable | Per-texture | Per-texture |
| Skin weights | 2 bones | 2 bones | 4 bones |
| LOD bias | 0.7 | 1.0 | 1.2 |
| Particle raycast budget | 16 | 64 | 256 |
| Realtime reflection probes | off | off | on |
| Texture mipmap limit | 1 (half res) | 0 | 0 |
| VSync count | 0 | 0 | 0 |
| Anti-aliasing | 0 | 0 | 0 |
| Shadowmask mode | Shadowmask | Shadowmask | Shadowmask |
| Async upload | 2 ms / 16 MB | 2 ms / 16 MB | 2 ms / 16 MB |

Default level on Android and iOS: **Medium**.

Two settings are zeroed on purpose. **Anti-aliasing** is owned by the URP asset — leaving a value
here double-books the setting and makes the effective MSAA level ambiguous. **VSync** is zero
because frame rate belongs to `Application.targetFrameRate`, which `GameRunner` sets; a vsync
counter on mobile fights the platform's own frame pacing.

The three URP assets are created by copying whatever pipeline asset the template shipped. Copying
the `.asset` file carries its script reference across, which is how this tooling configures URP
without referencing the URP assembly at all.

## 7. Deliberately not set

| | Why |
| --- | --- |
| Keystore / signing | Secrets. Never in a repo. |
| Scripting define symbols | Nothing needs one yet. `ALPHATOWN_VERBOSE_LOGS` is the first, when you want verbose logs in a release build. |
| Texture compression format | Revisit with real art — ASTC is the likely answer, but pick it against actual assets. |
| Physics / Time settings | Nothing depends on them yet. Fixed timestep is worth raising to 0.02–0.033 once there is movement. |
| `link.xml` | Only needed if Medium stripping removes something reflection depends on. Add on first symptom, not speculatively. |

## Version tolerance

Three Player Settings are applied by reflection: `SetIl2CppCompilerConfiguration`,
`SetIl2CppCodeGeneration` and `Android.optimizedFramePacing`. They are real wins, but they have
moved between Unity versions, and a hard reference to one that moved would fail the whole editor
assembly — taking the URP tooling down with it. If one is missing the Console says so and the run
continues.

The same principle covers quality levels: every field is written through `SerializedProperty` and
reported-then-skipped when absent, including `globalTextureMipmapLimit`, which was renamed from
`textureQuality` in Unity 6.
